# 프로젝트 잠시 보관

`잠시 보관`은 연결된 머신 사이에서 공유하는 목록 정리 기능이다. 프로젝트·worktree·터미널·프로세스·대화 기록을
닫거나 삭제하지 않으며, 절전 기능이 아니므로 실행 자원은 계속 사용한다.

## 사용

1. 프로젝트를 우클릭하여 `▣ 잠시 보관`을 선택한다. 연결된 worktree와 세션도 함께 보관한다.
   다른 머신의 프로젝트에도 전환 없이 우클릭할 수 있다.
   연결이 끊긴 머신도 목록에 캐시된 프로젝트가 있으면 보관할 수 있다.
2. 사이드바 하단의 테두리가 있는 고정 `▣ 보관함 N` 버튼을 누른다. 작은 화면에서는
   메뉴의 `▣ 보관함`으로도 들어갈 수 있다.
3. 기기 필터, 프로젝트·기기·메모 검색, 확인 필요 필터로 찾는다.
4. `다시 꺼내기` 또는 Enter로 기존 작업을 복원하고 이동한다. 새 세션을 만들지 않는다.
   연결되지 않은 머신에서는 복원 요청을 보내지 않는다.
5. 선택한 프로젝트에서 `메모 편집` 또는 목록 포커스의 `n`으로 다음 작업을 적는다.
   Enter는 저장, Esc는 편집 취소다. 한글 및 붙여넣기를 지원한다.

화살표·PageUp/PageDown·마우스 휠로 이동하고 Tab으로 검색/목록 포커스를 전환한다.
일반 Navigator 검색에도 `보관됨`으로 나타나며, 선택하면 보관함에서 명시적으로 복원한다.
아무 검색어가 없는 일반 Navigator 목록에는 보관 항목을 섞지 않는다.

## 상태와 보존

- 보관 프로젝트는 일반 프로젝트·에이전트 목록, 키보드 순회, 머신의 활동 집계에서 제외한다.
- 보관 시 이미 있던 Done/Blocked는 새 알림으로 올리지 않는다. 이후 상태 전환에서 발생한
  Blocked와 Done은 보관함 버튼에 따로 모으며, 배지를 누르면 확인 필요 항목을 보여 준다.
- 알림으로 프로젝트를 자동 복원하지 않는다. 오프라인 캐시는 현재 실행 알림으로 표시하지 않는다.
- 마지막 프로젝트를 보관하면 안내 화면을 보여 주고 숨겨진 터미널 입력을 차단한다.
- 기존 테마, 일반 목록의 행 전체 선택 배경, 서버 상태 감지, endpoint 프로토콜은 변경하지 않는다.
- **3.0.26부터 보관·복원·메모를 자동으로 공유한다.** 같은 서버에 연결된 다른 PC에도 반영된다.
  테마·글꼴·접힌 그룹·읽은 알림은 각 PC의 설정을 유지한다.
- 프로젝트를 실행하는 머신의 기존 `workspace.report_metadata` API로 공유한다.
  화면에 선택하지 않은 머신에도 반영하며, 서버 업데이트·재시작이 필요 없다.
- 변경 내용은 PC의 `client-shell/*.json`에 먼저 저장한다. 오프라인이면 `동기화 대기`로 표시하고
  연결 후 자동 전송한다. 통신 오류는 보관함 상단에 표시하며 목록과 메모는 보존한다.
- 보관 상태와 메모는 별도로 순서를 기록한다. 오래된 오프라인 변경은 나중에 완료된 복원을
  덮어쓰지 않는다. 동시에 같은 필드를 바꾸면 더 높은 변경 순서를 채택하며, 동일 순서는
  서버가 먼저 수락한 값을 따른다. PC 시계 차이는 마지막으로 수신한 순서보다 크게 보정한다.
- 기존 3.0.25 목록은 서버에 공유 기록이 없을 때 한 번 이전한다. 공유된 복원 기록이 있으면
  오래된 목록으로 재보관하지 않는다. 로컬 메모 원본은 업데이트 전 백업에 보존한다.
- 각 PC의 머신 프로필 ID가 달라도 실행 서버와 workspace를 기준으로 연결한다.
  해당 머신이 등록되어 연결된 클라이언트끼리 공유한다.
- **3.0.27부터 서버 재시작에도 보관 상태를 유지한다.** workspace ID와 정규화한 프로젝트
  저장 경로를 지속 식별자로 저장한다. 새 서버에서 같은 프로젝트를 확인하면 기존 기록과
  복원 tombstone을 새 연결에 이관하고, 중복 보관 기록은 상태·메모의 변경 순서대로 합친다.
  boot identity는 전송 대상 확인에 계속 사용한다.
- 3.0.25/26의 경로 없는 오래된 기록은 이름과 기존 pane ID까지 일치할 때만 자동으로 연결한다.
  다른 경로에서 재사용된 ID이거나 원본 프로젝트를 확인할 수 없으면 보관 항목·메모를 보존하고
  `연결 / 세션 확인 필요`로 표시한다.

## 세션을 유지하며 다시 열기

클라이언트 창만 닫고 다시 열면 실행 서버와 대화 세션은 유지된다. `herdr server stop`은
실행 서버와 모든 대화 프로세스를 종료하므로 화면 갱신이나 플러그인 적용 용도로 사용하지 않는다.
3.0.27의 관리되는 Windows `herdr` 실행 경로에서는 `server stop`에
`--confirm-server-stop`을 명시해야 실제 명령을 전달한다. 직접 `herdr.exe` 실행, API 호출,
OS 종료까지 막는 전역 보호 장치는 아니다. 서버 종료가 꼭 필요한 별도 유지보수에서는
먼저 모든 작업과 대화 복구 경로를 확인해야 한다.
